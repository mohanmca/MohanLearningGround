RHEL 9 Linux Host Networking Investigation

A practical, read-only Bash tutorial for Linux and Java developers diagnosing interfaces, bonds, routes, NetworkManager, and UDP sockets.

Safety: Every investigation command in this tutorial is read-only. It does not restart networking, modify a connection, change a route, kill a process, or send packets. Commands needing process details may require sudo.
Investigation path
  1. IPv4 addresses and interface types
  2. Bond health and active-backup behavior
  3. NetworkManager state
  4. Routes and policy rules
  5. UDP sockets and Java ownership
  6. Complete read-only script
  7. Final checklist

1. List IPv4 addresses

ip -br addr
ip -br -4 addr
ip -br -4 addr | awk 'NF > 2'

-br means brief, so each interface occupies one line. -4 restricts output to IPv4. The awk form retains rows with at least an interface, state, and address field. An address such as 169.91.200.111/25 is a unicast host address; it is unrelated to multicast merely because a multicast group might look similar, such as 239.91.200.111.

FieldExampleMeaning
Interfacebond0Kernel network device name
Administrative stateUPDevice has been enabled; it does not alone prove end-to-end reachability
Address169.91.200.111/25Host IPv4 address plus prefix length

Physical NIC versus logical bond

A physical NIC such as ens1f0 represents hardware. A bond such as bond0 is a logical device that owns the host IP and selects one or more member NICs for traffic. Applications normally bind to the bond address, not to a slave's address.

Java / UDP process
bond0
logical IP owner
ens1f0
active physical NIC
Switch / network
ip -d link show type bond
ip -br link
ip link show master bond0

ip -d adds device-specific details. The last command lists interfaces enslaved to bond0.

2. Inspect Linux bonding

ls -1 /proc/net/bonding/
cat /proc/net/bonding/bond0
cat /proc/net/bonding/bond1
cat /proc/net/bonding/bond3

Only read files that exist on your host. Each file is the kernel bonding driver's live view of one bond. Important fields are Bonding Mode, Currently Active Slave, each slave's MII Status, speed, duplex, and Link Failure Count.

for b in /proc/net/bonding/*; do
  [ -e "$b" ] || continue
  echo "== ${b##*/} =="
  grep -E 'Bonding Mode|Primary Slave|Currently Active Slave|MII Status|Slave Interface|Speed|Duplex|Link Failure Count' "$b"
  echo
done
ObservationInterpretation
Bond and active slave show MII Status: upPhysical link monitoring currently sees the path as healthy
Failure count increasesLink has flapped since the bond was created; compare timestamps and switch logs
Speed or duplex differs between slavesConfiguration/cabling may be inconsistent
No files under /proc/net/bondingNo kernel bond is currently registered, or the host uses another mechanism such as a team

Active-backup bonding

Mode active-backup (mode 1) uses one slave at a time. The standby takes over when link monitoring declares the active slave unhealthy. It provides redundancy, not bandwidth aggregation. Depending on primary and primary_reselect, traffic may or may not return to the preferred NIC after recovery.

Do not test failover on a production host by bringing a slave down unless the change is approved and an out-of-band recovery path exists. This tutorial only observes state.

3. Check NetworkManager

nmcli -t -f NAME,DEVICE connection show --active
nmcli device status
nmcli connection show --active
nmcli -f GENERAL,IP4 device show bond0

A connection is a saved or active NetworkManager profile; a device is a kernel interface. Their names can differ. The terse option -t is convenient for scripts.

Device stateMeaning
connectedNetworkManager activated a profile on the device
unmanagedNetworkManager intentionally does not control the device
connected (externally)The device has usable configuration created outside the active NetworkManager profile workflow; NetworkManager observes it without claiming the original configuration
disconnectedManaged, but no active connection profile is applied

On a bond, slave devices can legitimately have no IP address. Check that the bond owns the intended IP and that the active profile maps to the intended device.

4. Check routes and policy rules

ip -4 route show
ip rule show
ip route get <destination_ip>

The first command lists the main IPv4 routing table. ip rule shows policy-routing selection rules, which may direct traffic to other tables based on source, marks, or priority. Replace <destination_ip> with a real IP, without angle brackets:

ip route get 169.91.200.50
ip route get 239.91.200.111

ip route get asks the kernel which route it would use. Inspect the returned device, next hop, source address, and table. It performs a lookup; it does not send a packet.

Multicast note: Routes choose an egress interface, but multicast reception also depends on the application joining the group, socket binding, local firewall, IGMP state, and upstream switch multicast behavior.

5. Inspect UDP sockets

ss -uapn
ss -uapn | head

ss inspects kernel sockets. The flags mean: -u UDP, -a all sockets, -p process information, and -n numeric addresses and ports. Use sudo ss -uapn when another user's PID or process name is hidden.

OutputMeaning
0.0.0.0:9000Socket is bound to port 9000 on all local IPv4 addresses; it does not mean “the whole world”
169.91.200.111:9000Socket is bound specifically to that local address and port
UNCONNNormal for an unconnected UDP socket; UDP has no TCP-style connection state
users:(("java",pid=1234,fd=87))Java PID 1234 owns the socket through file descriptor 87

Java processes owning UDP sockets

sudo ss -H -uapn | awk '
  /users:\(\(\"java\"/ {
    if (match($0,/pid=[0-9]+/)) {
      pid=substr($0,RSTART+4,RLENGTH-4)
      count[pid]++
    }
  }
  END {
    printf "%-10s %s\n", "PID", "UDP_SOCKETS"
    for (pid in count) printf "%-10s %d\n", pid, count[pid]
  }'

This counts socket rows reported for each Java PID. A single socket can appear in ways that make this an investigative count rather than an application-level message/channel count. Confirm the command line safely with:

ps -p <pid> -o pid,user,etimes,cmd --no-headers

Count all UDP sockets by process and PID

sudo ss -H -uapn | awk '
  {
    name="unknown"; pid="-"
    if (match($0,/users:\(\(\"[^\"]+\"/)) {
      name=substr($0,RSTART+9,RLENGTH-10)
    }
    if (match($0,/pid=[0-9]+/)) {
      pid=substr($0,RSTART+4,RLENGTH-4)
    }
    count[name SUBSEP pid]++
  }
  END {
    printf "%-24s %-10s %s\n", "PROCESS", "PID", "UDP_SOCKETS"
    for (key in count) {
      split(key,a,SUBSEP)
      printf "%-24s %-10s %d\n", a[1], a[2], count[key]
    }
  }' | sort

Ephemeral port range

sysctl net.ipv4.ip_local_port_range
cat /proc/sys/net/ipv4/ip_local_port_range

When an application binds to port 0, Linux normally selects an available local port from this range. Explicitly bound service ports can be outside it. Port exhaustion investigation should also consider application lifecycle, namespace boundaries, and socket counts.

6. Complete read-only investigation script

Save the following as rhel9-network-investigate.sh, make it executable, and run it. An optional first argument performs a route lookup.

chmod +x rhel9-network-investigate.sh
./rhel9-network-investigate.sh
./rhel9-network-investigate.sh 239.91.200.111
The script uses only inspection commands. It records command availability and permission limitations rather than aborting the entire report.
#!/usr/bin/env bash
set -u

DESTINATION_IP="${1:-}"

section() { printf '\n\n==== %s ====\n' "$1"; }
run() {
  printf '\n$'
  printf ' %q' "$@"
  printf '\n'
  "$@" 2>&1 || printf '[command exited with status %d]\n' "$?"
}
have() { command -v "$1" >/dev/null 2>&1; }

printf 'RHEL 9 host networking investigation\n'
printf 'Generated: '; date --iso-8601=seconds
printf 'Host: '; hostname
printf 'Kernel: '; uname -r
printf 'User: '; id
printf 'Safety: read-only inspection; no network state is changed.\n'

section 'IPv4 addresses and links'
if have ip; then
  run ip -br -4 addr
  run ip -br link
  run ip -d link show type bond
else
  printf 'ip command not found\n'
fi

section 'Kernel bonding status'
shopt -s nullglob
bonds=(/proc/net/bonding/*)
if ((${#bonds[@]} == 0)); then
  printf 'No bond status files found under /proc/net/bonding.\n'
else
  for b in "${bonds[@]}"; do
    printf '\n== %s ==\n' "${b##*/}"
    grep -E 'Bonding Mode|Primary Slave|Currently Active Slave|MII Status|Slave Interface|Speed|Duplex|Link Failure Count' "$b" || true
  done
fi
shopt -u nullglob

section 'NetworkManager'
if have nmcli; then
  run nmcli -t -f NAME,DEVICE connection show --active
  run nmcli device status
  run nmcli connection show --active
  while IFS= read -r bond; do
    [ -n "$bond" ] && run nmcli -f GENERAL,IP4 device show "$bond"
  done < <(ls -1 /proc/net/bonding 2>/dev/null || true)
else
  printf 'nmcli not found; NetworkManager may be absent or tools not installed.\n'
fi

section 'Routes and policy rules'
if have ip; then
  run ip -4 route show
  run ip rule show
  if [ -n "$DESTINATION_IP" ]; then
    run ip route get "$DESTINATION_IP"
  else
    printf 'No destination argument supplied; skipping ip route get.\n'
  fi
fi

section 'UDP sockets'
if have ss; then
  run ss -uapn
  printf '\nUDP socket rows grouped by process and PID:\n'
  ss -H -uapn 2>/dev/null | awk '
    {
      name="unknown"; pid="-"
      if (match($0,/users:\(\(\"[^\"]+\"/))
        name=substr($0,RSTART+9,RLENGTH-10)
      if (match($0,/pid=[0-9]+/))
        pid=substr($0,RSTART+4,RLENGTH-4)
      count[name SUBSEP pid]++
    }
    END {
      printf "%-24s %-10s %s\n", "PROCESS", "PID", "UDP_SOCKETS"
      for (key in count) {
        split(key,a,SUBSEP)
        printf "%-24s %-10s %d\n", a[1], a[2], count[key]
      }
    }' | sort
else
  printf 'ss not found; install iproute tools through the approved host process.\n'
fi

section 'Local ephemeral port range'
if have sysctl; then
  run sysctl net.ipv4.ip_local_port_range
else
  run cat /proc/sys/net/ipv4/ip_local_port_range
fi

section 'Investigation notes'
printf '%s\n' \
  'UP is not proof of application reachability.' \
  'A healthy bond is not proof that routes, firewall, multicast joins, or switches are correct.' \
  'Missing process details in ss usually require elevated privileges.' \
  'Correlate findings with application logs and approved network telemetry.'
